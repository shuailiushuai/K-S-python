### 1.1 完整的D2需求分配算法

**状态：** ✅ **已实现**

**C++参考：** `fun_KS_consumption.h`，第18-92行

完整的D2需求分配算法已在Python中实现，包含完整的未满足需求追踪。

#### 实现细节

**方法：** `ConsumptionSector.allocate_demand_to_firms(nominal_demand: float) -> float`

**位置：** `python/model/country.py`，第384-496行

**算法流程：**
1. 为市场份额(f2)、价格(p2)和可用供应(sup2)创建临时向量
2. 初始化企业需求累加器(_D2)和未满足需求追踪(_l2)
3. 基于市场份额迭代分配需求：
   - 按每个企业的市场份额比例分配需求
   - 如果企业能供应所有需求：完全满足
   - 如果企业不能供应所有需求：供应可用数量，在_l2中追踪未满足需求
   - 重新调整剩余企业的市场份额
4. 继续循环直到所有需求分配完毕或没有更多供应

**核心特性：**
- ✅ 完全匹配C++算法
- ✅ 正确的_l2（未满足需求）追踪
- ✅ 当企业供应耗尽时进行迭代重新分配
- ✅ 每次迭代后重新调整市场份额
- ✅ 安全检查防止无限循环

### 2.1 Market vs Sector术语

**发现：** 混用术语（Market vs Sector）是**有意且正确的**。

#### C++源代码的证据

原始C++代码使用混合术语：

```c
// 文件头使用"MARKET"
fun_KS_labor.h:      "LABOR MARKET OBJECT EQUATIONS"
fun_KS_capital.h:    "CAPITAL-GOODS MARKET OBJECT EQUATIONS"
fun_KS_consumption.h: "CONSUMER-GOODS MARKET OBJECT EQUATIONS"
fun_KS_financial.h:   "FINANCIAL MARKET OBJECT EQUATIONS"

// 内部变量使用"Sector"
WRITE_EXT( countryE, capSec, SEARCH( "Capital" ) );      // capSec
WRITE_EXT( countryE, conSec, SEARCH( "Consumption" ) );  // conSec
WRITE_EXT( countryE, finSec, SEARCH( "Financial" ) );    // finSec
WRITE_EXT( countryE, labSup, SEARCH( "Labor" ) );        // labSup
```

**结论：** 原始C++作者（Marcelo C. Pereira教授）使用了混合术语，表明这是有意的。

### 2.2 为什么不同名称是正确的

| 组件 | 名称 | 原因 |
|------|------|------|
| 劳动力 | **Market** | 它是一个匹配机制（双边搜索） |
| 资本/消费/金融 | **Sector** | 它们是生产部门（聚合器） |

这反映了它们本质的根本差异：

**劳动力市场：**
- 复杂的双边匹配算法
- 跨部门（工人可以在任一部门工作）
- 678行匹配逻辑
- 独立机制

**资本/消费/金融部门：**
- 容器/聚合器对象
- 从企业/银行收集统计数据
- 与Country协调紧密耦合
- 主要是聚合

### 2.3 文件组织原理

#### 当前组织
```
python/model/
├── labor.py         # 678行 - LaborMarket（匹配机制）
├── country.py       # 2147行 - Country + 3个Sector（协调）
├── firm1.py         # 388行 - Firm1代理
├── firm2.py         # 573行 - Firm2代理
├── worker.py        # 367行 - Worker代理
├── bank.py          # 534行 - Bank代理
└── statistics.py    # 690行 - 统计收集器
```

#### 为什么这种组织是最优的

**劳动力市场独立的原因：**
1. **功能独立性：** 复杂的匹配算法，独立于生产
2. **跨部门性：** 服务于资本和消费两个部门
3. **可重用性：** 可以独立测试和理解
4. **大小：** 678行证明需要单独文件

**部门在country.py中的原因：**
1. **紧密耦合：** 与Country时间步协调频繁交互
2. **聚合焦点：** 主要收集和聚合企业级数据
3. **循环导入：** 分离会需要复杂的导入管理
4. **验证：** 相关代码在一起时更容易与C++对比

#### 与C++文件的映射

| Python文件 | C++文件 | 原理 |
|-----------|---------|------|
| country.py | fun_KS_country.h + fun_KS_capital.h + fun_KS_consumption.h + fun_KS_financial.h | 协调和聚合 |
| labor.py | fun_KS_labor.h | 匹配机制 |

这种多对一映射有助于验证，同时保持良好的代码组织。
